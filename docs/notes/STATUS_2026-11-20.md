## Stage design as of 2c75ac2d (753ac78e differs only as noted)
- **Staged arm** (10 syscalls, each flushed to the PC): arm0 read-only checks (incl. full 15-byte
  icc_query_nowait prologue) · arm1 text patches · arm2 kernel copy · arm3 scanout geometry ·
  arm4-7 contig elf/region/boot/fb (**M_NOWAIT x4, userland retry**) · arm8 pmap_extract + ELF copy · arm9 finish.
- arm7 falls back to the OrbisOS scanout surface if no contiguous block.
- Takeover: rendezvous (7 APs parked) -> display to linear on our surface -> **Bus Master off, 5 ms
  drain, IOMMU off**, PCI MSI/INTx off, Aeolia MSIs off, HPET off, GPU engines halt (cyan 11-18) ->
  memory map -> own page tables -> 180 s hold -> upl_load (FVs in place) -> EDK II.
- 753ac78e: Bus Master off only on GbE 14.1, SDHCI 14.3, xHCI 14.7 (cyan 12/14/16); HDA 01.1, AHCI 14.2,
  DMAC 14.5 left on (grey 11/13/15); hold 30 s.
- Memory map: RAM only inside OrbisOS's live `phys_avail` (kbase+0x2216a80) and WB in the DMAP;
  region/elf/boot/fb/kernel-copy pages reserved. The UEFI heap (own-memory-only map) is compiled
  out (`-DDB_ARM_HEAP`), because its allocations need large contig blocks (fact 1/3).
